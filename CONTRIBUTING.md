# Contributing to Night Fleet

Thanks for your interest in Night Fleet. Bug reports, translations, accessibility feedback and pull requests are welcome.

## Reporting bugs

Please open an issue with:

- what you did, what you expected and what happened instead;
- the screen or mode where it happened, and the difficulty if it applies;
- your device model and Android version;
- a screenshot when the problem is visual.

## Development setup

1. Install a JDK (17 or newer) and the Android SDK with platform 37.
2. Point Gradle at them:

   ```bash
   export JAVA_HOME=/path/to/jdk
   export ANDROID_HOME=/path/to/android-sdk
   ```

3. Build and test:

   ```bash
   ./gradlew :core:test :leveltool:test :app:testDebugUnitTest
   ./gradlew :app:assembleDebug
   ```

   Or run everything the CI runs, including lint and the permission and dependency checks:

   ```bash
   bash tools/verify.sh
   ```

No emulator is needed. Game rules belong in `:core` and are tested on the JVM. UI logic that can be separated from Compose (theme tokens, string resources, geometry) is tested on the JVM too; the rest of the UI is checked on a real device.

## Commit messages

- Write messages in English, in the imperative mood, with a type prefix: `feat:`, `fix:`, `content:`, `build:`, `ci:`, `docs:`, `test:`, `refactor:`, `chore:` (for example `feat: add salvo rule`).
- **Do not add AI attribution.** No `Co-Authored-By` trailers, no "Generated with" lines and no tool names in the message.
- Enable the commit hook once per clone. It rejects those lines and checks the prefix:

  ```bash
  git config core.hooksPath tools/git-hooks
  ```

  Do not bypass it with `--no-verify`.

## Pull requests

- Create a branch from `develop` and keep each pull request focused on one change.
- Make sure `bash tools/verify.sh` passes and say in the description how you tested the change, including the device for UI changes.
- Add or update unit tests when you change rules, the AI, persistence or content tooling.
- Keep commits small.

## Coding conventions

- New code is in English: identifiers, comments, log and error messages.
- Every text the player sees goes in `app/src/main/res/values/strings.xml` (English), with a translation in `values-pt/strings.xml` (European Portuguese). Do not hardcode visible text in Kotlin.
- Colour values live only in `app/src/main/java/pt/tiago/nightfleet/ui/theme/`. Screens read the tokens from `FleetTheme`.
- Match the style of the surrounding code. Comments explain *why*, not *what*.
- `:core` must stay free of Android, clock and platform-random dependencies, so that results are reproducible. Randomness comes from the versioned `SplitMix64` only.
- Any change to the engine's or the AI's observable behaviour needs a new version constant and regenerated certificates.
- Never use the word "Battleship" for the game, in the code, the assets or the store texts. Use "naval battle".

## Launcher icon and store images

The launcher icon's vector drawables (`app/src/main/res/drawable/ic_launcher_*.xml`) and the store images (`fastlane/metadata/android/*/images/icon.png` and `featureGraphic.png`) are generated by `tools/render_icon.py` from one geometry. Do not edit those files by hand: change the script and run `python3 tools/render_icon.py`. The store texts in `fastlane/metadata/android/` must stay within the F-Droid limits (title 50, short description 80, full description 4000, changelog 500 characters); `ci.yml` checks them.

## Permissions and dependencies

Night Fleet requests only `VIBRATE` and has no network permission. Do not add permissions, analytics, ads, Google Play Services or Firebase, and keep the release build free of non-free dependencies. `tools/check_permissions.sh` and `tools/check_deps.sh` enforce this.

## Translations

To add a language, copy `app/src/main/res/values/strings.xml` to `values-<code>/`, translate every translatable string and plural, and leave the strings marked `translatable="false"` out. Add the locale to `app/src/main/res/xml/locales_config.xml`. `StringsParityTest` checks that the keys and placeholders match. Check the result on a device, because Portuguese and English lengths differ.
